# 从源材料到可用的学习笔记

简体中文 · [English](teaching.md)

撰写或实质修改知识单元前，完整阅读本指南。交付内容使用[笔记表单](../templates/lesson.md)，文件操作遵循[工具参考](tools.zh-CN.md)。课程档案决定范围、语言和考核形式；本指南不预设科目或考试类型。

## 1. 写前确定范围

阅读指定源章节和相关现有笔记，在笔记或撰写记录中建立简短的覆盖表：

| 核验过的来源位置 | 目标、论点或操作 | 需要解释的原因 | 对应讲解、图或检查的位置 |
|---|---|---|---|
| 实际页号或小节 | 来源要求掌握的内容 | 缺少的前置或推理步骤 | 笔记如何解决 |

覆盖指定章节的每个实质步骤。定义、证明、实验、自测和学习重点均限于约定来源及理解它所需的最小推理。每个新增例子必须解释一个可定位的源步骤。可执行要求不授权增加软件接口知识、新评价指标或完整应用；解释局部步骤的小计算可以满足需要，但应说明具体演示了哪一部分。

遵循源材料的符号、约定和操作顺序。本课已经包含的陌生概念需要解释；另一门课的文本搜索没有结果，不能证明它超出范围。检查相关前置课程的指定来源，区分其用途，在使用前定义对象。合并考核可能涉及多门课程，其中的必要前置仍须掌握，即使学习者尚未复习对应科目。

源公式疑似不一致时，检查原页并验证问题，在对应位置说明已核实的不一致及采用的约定。无法确认的内容记录为待核。不静默替换符号，不将已确认的错误继续作为有效公式。

对疑似 recap，比对两份源材料及旧笔记；在衍生笔记中把核实的重复内容改成准确回指，保留新增知识。原始材料和页码保持完整。旧笔记仍是框架时注明缺口，不能暗示已有完整讲解。

## 2. 建立推理链

沿 **目标 → 输入 → 中间对象与操作 → 推导或论证 → 可验证的结果** 组织。每次转换都说明已知什么、计算或推断什么、操作为何服务于目标、得到什么，以及结果仍无法确定什么。

新符号在公式前定义：含义、类型、维度，以及适用时的坐标系、单位和读法。学习者需要自行猜测的步骤，应给出代入和中间等式。非数学学科同样需要解释证据、推论、假设和论证边界。

追问是诊断依据。一组相关追问可能暴露前置链缺失，应按知识依赖组织回答，并核对各个问题是否得到解释。用户要求更新笔记时，再将这条知识链整合进所属章节。组织主线始终是源材料的任务。

分开标注本课证据、跨课程前置、推导和辅助直觉。适用时解释去掉组件或改变假设的结果，区分数学必要、数值必要和经验改进。不为无关科目强行设计消融实验。

## 3. 让机制可见

根据实际理解困难选择表达方式：几何或关系用图，图像处理用对应的中间图像，对象变化用表，代数用小计算，论证用标注过的文本证据。连接的阶段尽量使用同一输入，以便比较变化；若统一例子需要无关机制，则分别使用局部例子。

图紧跟对应讲解，图下说明输入、操作、输出和关键观察。标签须可读，区分源图、示意图、构造教学数据和计算结果。集中放置截图且不解释，无法满足可视化要求。

报告数值和生成图的代码须实际执行，同时核验数值与图像。无需代码的论证则对照来源检查。局部演示不能宣称完整运行算法。不把未经测试的教学代码交给学习者排查。

## 4. 完成学习闭环

正式单元具备六种功能：目标与来源、符号与前置、推理、例题核验、独立复现、收口。保留这些功能，仅有标题不足以达标；确实不适用的部分说明原因，避免填入无关内容。

可执行知识点使用 **Predict → Run → Break it → Reproduce**：

- Predict：展示结果前提出可判断的预测题。
- Run：展示实际结果，并联系源材料中的操作。
- Break it：改变一个相关假设或输入，观察结果，解释适用边界。
- Reproduce：提供空白作答区，要求独立重建结果或解释。

文本、历史或概念类主题可对应为：有证据依据的预测或论点、完整分析、反例或假设变化、独立重建。无需强行使用代码。

完整笔记包含例题答案和符合考核形式的示范作答。自测答案放在默认折叠区或有明确链接的答案章节，与题目隔离。现场测验等待学习者作答后揭晓答案；这条要求不影响笔记答案的完整性。收口不能写成“等待学习者回答后补充”。

方法类口试可采用 **Problem → Solution → Why → Boundary** 收口。其他考核可能要求证明、论文提纲、文本解释或操作展示。提供简短结论和有来源依据的学习重点；导师建议应标明身份，不能虚构考频。

## 5. 分别检查四个方面

| 检查项 | 交付前所需证据 |
|---|---|
| 来源覆盖与范围 | 来源映射中的每步都有讲解；新增概念都有必要用途。 |
| 机制解释 | 公式前定义符号；中间推理和操作原因明确；知识链到达预定结果。 |
| 示例一致性 | 输入、顺序、约束、单位、产物符合来源；图文相邻并有图解；局部演示明确标注。 |
| 文件验证 | 计算与正文一致；链接存在；适用代码在 Notebook 目录的干净内核中通过；答案与原有作答保留。 |

检查程序只能证明其文档明确承诺的技术性质。前三项及答案质量需要人工审查。未核验部分如实说明。

学习者指定旧笔记为范例时，写前实际检查一个相关完整单元及其真源、生成文档和已有输出。复用教学功能，并按当前要求检查内容深度、符号、图的位置和答案质量。受认可的旧笔记仍可能有缺点。新工作区无需依赖私人范例文件，本指南和空白表单提供初始标准。

## 6. 分开交付与记录

遵循约定的交付位置和范围。疑问句只要求在聊天中回答，不授权修改文件。用户明确要求更新笔记时，将解释整合进笔记，聊天只报告变化、验证和文件链接，不重复全文。当“回答正确才继续”这一条件没有满足时，不进入后续单元。

分别记录材料就绪、自述阅读或复习完成、辅助练习、独立展示。明确记录主动跳过的内容，不能标成 recap 或已完成教学。学习者可以结束其选定范围的复习，同时保留未填笔记或未测知识点。掌握程度只由观察到的独立表现支持。模板审计本身不增加学习进度。

问题重复出现时，定位缺少的判断或冲突规则，修改负责该事项的指南及执行入口。避免堆积特定课程的例外，也避免在每个文件重复规则。重新检查此前失败的场景，并区分文档检查、程序执行和实际学习会话。
