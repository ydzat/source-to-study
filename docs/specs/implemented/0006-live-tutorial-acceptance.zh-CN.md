# 真实会话教程验收

简体中文 · [English](0006-live-tutorial-acceptance.md)

## 问题

文档与脚本测试不能证明自然短句能真正生成并逐步完善可用笔记。

## 决策

保留教程的自然短句，在对应 Skill 中明确其含义：预处理包含来源地图和经过验证的框架；开始知识点和追问默认更新已有笔记；聊天报告结果，不复述讲义。用户明确要求仅提取、仅聊天、测验或更小范围时，仍以该要求为准。

在已初始化的隔离副本中使用真实独立 Agent 验证这一约定，不模拟回复，也不向它注入验收标准。检查实际产物、来源依据、执行结果和迭代差异。

## 考虑过的替代方案

伪造 Agent 无法测试发现和行为；把详细验收标准告诉被测实例会污染测试；直接操作私人笔记会危及真实学习状态。

## 影响

- 学习者无需重复内部流程，也不必每次明确要求更新 Notebook。
- 缺失的学习选择、保护未保存编辑仍可能需要一句简短回复，教程不掩盖这些确认。
- Skill 保持英文规范指令，面向学习者的教程保持双语。没有把提示词加长，也没有把示例专用知识塞进教程。
- 本地日志、生成笔记、快照和测试内容均保留在忽略目录，不作为随仓库发布的参考答案或真实学习进度。

## 验证

2026-09-27 在 Windows 上测试，使用 Codex CLI `0.158.0-alpha.2.1` 及已有模型配置、Python 3.12.14 和 STS 锁定环境。本机 Codex 必须加 `--no-daemon`；这是宿主兼容处理，不是 STS 的通用前置要求。子会话保留 `workspace-write` 权限。

### 实测问题及修正

- 首次预处理停在 PDF 提取。修正准备 Skill 后，同一句话能提出划分、询问学习选择，并在确认后生成框架。
- 首次 K01 只在聊天中讲解，笔记未变。修正教学 Skill 后，笔记成为默认交付面。
- 一次追问虽修改笔记，仍在聊天中重复例子和表格。收紧交付规则后，新会话的澄清请求只返回简短答案及文件、验证说明，没有再输出一篇讲义。
- 旧会话未重新加载已修改的 Skill，因此修正行为通过新会话复测；随后在同一持续会话中完成“预处理核验 → K01 → 追问 → K02”。最后的精简交付改动另外通过新会话验证。

### 产物检查

| 检查点 | 观察结果 |
|---|---|
| `帮我预处理 summarizing_distributions.pdf。` | 12 个单元完整覆盖 41 页，每页恰好归属一次；原 PDF 未改，来源资源与框架通过验证。新会话重跑能安全复用这些产物。 |
| `我们从 K01 开始吧。` | K01 对应 PDF 第 2–8 页，包含符号说明、逐步计算、原文图及图解、两个代码单元和回忆题；后续单元未讲。 |
| `为什么同一组数据可以有不同的“中心”？我没太理解。` | 只修改 K01，澄清内容整合在公式之前。学习者单元保持完全一致，包括明确标记的保留测试文本。 |
| `这部分我明白了，继续 K02 吧。` | 只修改 K02，对应 PDF 第 9–11 页；K01 和学习者单元完全未变。没有把自述理解记录为独立掌握。 |
| 新会话：`K01 里的 c 是数据里的某个数吗？` | 只修改 K01 对应说明；验证了简短交付和学习者内容保留。 |

独立最终检查通过 115 处本地资源引用及 3 个代码单元；以 Notebook 所在目录为工作目录、干净内核从头执行。另以 inline backend 执行，实际得到一张包含两条代价曲线的 PNG，并检查了图片和数值输出。标准检查及 inline 检查均未改写输入 Notebook。例子复现了源文数值：绝对偏差和在 4 处最小为 20，平方偏差和在 6.8 处最小为 134.8；31 支球队的数据和为 634，中位数为 20，众数为 18。

现有 20 项自动化测试通过，包括真实内核及本地 Jupyter 服务测试。两个修改过的 Skill 通过格式校验，公开文档链接及双语配对通过文档测试。

### 边界

这是一轮中文、Agent 驱动的学习者模拟，不证明真实学习效果或所有 Agent/模型的行为。测试使用已初始化的环境，覆盖部署后的使用流程，不是全新机器安装测试。没有实际点击 GUI 快捷键或完整检查浏览器排版；内核图片输出及本地服务测试不能替代这项声明。英文对话行为和卡片导出不在本轮范围内。宿主警告及失败试次保留在本地证据中。没有修改私人课程资料或真实学习进度。
