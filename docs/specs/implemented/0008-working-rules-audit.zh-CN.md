# 工作规则与 Markdown 一致性

简体中文 · [English](0008-working-rules-audit.md)

## 问题

导师规则缺少参考工作区中可复用的表达、授权、证据与编辑约束。教学 Skill 和教程把疑问句直接视为修改笔记的授权。部分历史决定使用当前指令语气，部分中文存在不符合要求的简写。

## 决定

[AGENTS 双语规则](../../../AGENTS.zh-CN.md)补齐通用表达、疑问句授权、证据、安全编辑和验证约束。教学 Skill、入门教程、教学指南和课程表单区分问题与明确修改请求。历史决定标注被替代的行为，保留原有测试观察。

检查根目录、guides、docs、templates、examples、.agents/skills/ 中此前已有的全部 50 个维护中的 Markdown 文件，本记录新增两个语言文件。依赖目录、生成的验收工作区、私人学习状态和来源材料未纳入修改。没有把私人课程路径、考试事实或固定解释器选择写入模板。

## 考虑过的方案

复制整份参考规则会引入私人课程路径、考试事实和运行环境假设；只改措辞又会保留疑问句触发编辑的行为。采用基于本地参考规则和当前文档的定点修改。

## 影响

- 疑问句只回答，不推定文件修改授权；明确教学或编辑请求继续按对应流程处理。
- AGENTS 覆盖表达、证据、范围、安全编辑和如实验证，无需访问私人父项目。
- 教程、Skill、表单和当前决定一致；历史观察保留原有身份。
- 中英规则一致，链接、Markdown 结构和 Skill 格式验证通过。
- 不改运行代码、依赖、原始材料或学习记录。

## 验证与局限

文本搜索可能把正式术语和引文误判为表达问题，须结合上下文判断。历史验证不能改写成新行为已通过的证据。本轮以文档和场景检查验证，不据此声称端到端 Agent 行为已经复测。

2026-09-28，通过现有环境的离线 `uv run --no-sync` 运行 `python -m unittest discover -s tests -p test_docs.py -v`，文档测试通过，检查公开相对链接、语言配对、JSON 示例及文件末尾换行。改动的 sts-study-session、sts-setup 均通过 `quick_validate.py`；`git diff --check` 未报告空白错误。

人工对照相关文档检查了以下判断：

| 请求或条件 | 当前规定 |
|---|---|
| “这个符号是什么意思？” | 在聊天中给出足够解释，不改文件，也不附送实施邀请。 |
| “请解释，并补充到 K01 笔记。” | 修改指定章节，验证后简述结果并链接文件。 |
| 已约定笔记流程中的“开始 K01” | 撰写指定单元，后续单元不动。 |
| “回答正确才继续。” | 核对条件后决定是否推进。 |
| 仅部署环境 | 验证环境，不改变课程内容和学习进度。 |
| 脚本失败 | 检查移除敏感内容后的相关错误，保留验证，报告未解决问题。 |
| 旧验收在提问后修改了笔记 | 保留日期化观察，明确其与当前规则的区别。 |

未改运行代码、依赖、原始材料或学习记录。没有重跑历史 20 项运行测试，也没有把旧结果作为本轮验收。未进行新的独立 Agent 或图形界面验收。本轮检查支持文档一致性和 Skill 格式有效性，实际运行行为尚未在本轮复测。
